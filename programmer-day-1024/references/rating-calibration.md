# 判级校准：固定证据口径与相邻等级

用于 `1024-8d-v3` 首次判级或有新证据时的复核，与 [评分规则](scoring-and-chart.md) 配合使用。以下都是教学用的虚构短例，不是任何用户的预置评级，也不是已经完成的评审者一致性实验。

## 先固定口径，再判断等级

始终评价**可见证据中用户已作出的表达、选择和调整**。一份文档可以证明其中明确归属于用户的要求或方法，不能仅凭文笔、长度、术语或完整排版推断执行水平。用户亲自提出或明确选定的验收条件，本身可支持“目标表达”；“以后要验证”的文字不能支持已经验证的 E。来源不明的漂亮文档、Agent 自动生成而用户未作具体选择的内容，不当作用户的直接贡献。

按以下顺序处理，不先看期待的总分或海报形状：

1. **固定证据快照。** 在工作上下文记录本次可见来源范围、截止位置、规则版本和证据编号；优先使用当前已授权材料。将记录区分为用户要求/决策、已发生的执行反馈、对应结果/检查。用户陈述可以作为陈述证据；未经佐证的“总是成功”等自评不能直接充当重复有效的结果。
2. **逐格匹配。** 对八维各自的 A、B、C、E，记录 `证据编号 → 可观察事实 → 达到的门槛 → 下一等级缺什么`。同一材料可支撑不同格，但须写出各格不同的事实，不能复制一个泛泛的“有方法”。
3. **按门槛取级。** A/B 的 2 级须有针对本指标的具体可执行选择；3 级须同时说明适用对象/目标、实际做法，以及该任务中会改变决定的重要条件；4 级须在 3 级基础上，有同一问题的“实际反馈或暴露的问题 → 用户作出的具体校准 → 与反馈相符的修订”链路。修订可为用户已更新的要求或方案，不要求最终成品已完成；最终成效另看 E。不能拼接无关联事件制造闭环。没有实际冲突时，不要求用户人为制造冲突；不要求增加字数、工具、参与者或部署步骤。
4. **处理边界。** 从低级逐项检查到拟给等级，更高门槛证据缺失时取已经证明的较低级；证据冲突且无法消解时记录争议，不选择更乐观的读法。C/E 独立判定，A/B 达到 3 或 4 不会自动带动 C/E 升级。整维无直接 A/B 证据则为 `null`。
5. **冻结并复用。** 保存已核验的分项等级与上述简短理由，再计算一位小数。只改排版或口号时复用原有台账和分数。发现判据应用错误时可更正，但要记录原等级、被误读的证据和更正理由；新来源或规则升级需要重新判级。不要为了得到相同数字而隐瞒错误，也不要反复换解释以挑选更好看的分数。

缺证不是能力低。内部将判级依据记为“明确”或“存在边界”，边界项指出缺失门槛；不把这两个标记折算为额外加减分。对外可用一句“根据当前可见记录的活动画像”说明范围，无须展示私人台账。

独立 Agent 仍可能对证据作出不同判断；本规则提供可核对的裁决程序，**不承诺未经实测的评审者一致率**。发生分歧时比较证据编号和具体门槛，不取两人的平均数、不编造半级。公式对同一组整数评级确定，不等于首次阅读自然语言证据必然产生相同评级。

已实际运行且明确标注的受控验证，也能提供执行反馈；不能把测试情况写成线上事故。文档本身就是任务成果时，试读、校对、调用等可构成相关验证，不要求一律部署。

## 八维的相邻等级示例

每张表的 A、B 是分别判定的示例：只有相应列中的证据出现，才支持该格升级。实际用户完全可以 A=3、B=2。例子中的受众、样张、工具和约束可替换，判断的是关系是否明确，并非必须使用这些场景。

### 1. 创意构思

| 边界 | 指标 A：想法与目标/受众/场景 | 指标 B：组合价值与实现路径 |
| --- | --- | --- |
| 2 → 3 | “做程序员节海报，加技能元素”可执行，但用途未明，为 2；“用于同事之间分享，突出使用 AI 的长处而非模型广告”，明确目标和排除项，支持 3。 | “把雷达图和口号放一起”为 2；“雷达图展示长处，口号提炼主亮点，长文移到图外保证手机阅读”，给出各部分作用与实现安排，支持 3。 |
| 3 → 4 | 上述完整想法但未看实际效果仍为 3；看到初稿被误读成工具广告后，用户要求以个人称号为主体并在修订中落实，支持 4。 | 仅提出排版预案仍为 3；初稿表格挤占主标题后，用户根据样张选择雷达图与两句短文，修订落实对应组合关系，支持 4。 |

### 2. 目标表达

| 边界 | 指标 A：成果与验收要求 | 指标 B：边界、约束与优先级 |
| --- | --- | --- |
| 2 → 3 | “输出一张含分数的 PNG”为 2；“输出竖版 PNG，八维名称、10 分制一位小数必须入图，逐项对照数据”，明确可检查成果，支持 3。 | “维度标签至少 24px，三句文案全部保留”为 2：约束具体但未处理空间冲突；“保留八维数字和称号，空间不够先缩短能力文案，不缩小数字”，给出优先级，支持 3。“需要好看、内容要全”仍只是 1。 |
| 3 → 4 | 条件写得完整但没经历反馈仍为 3；用户发现图片数字正确而点位错误，把验收补成数字与半径都核对，修订采纳该条件，支持 4。 | 仅列优先级仍为 3；样张确实拥挤后，用户明确保留字号、删重复标签，修订落实这次权衡，支持 4。 |

### 3. AI统筹

| 边界 | 指标 A：人机分工与任务匹配 | 指标 B：能力选择、顺序与依赖 |
| --- | --- | --- |
| 2 → 3 | “让 AI 研究，再让我看”为 2；“AI 按来源整理备选，我按预算决定，选定后再由 AI 排版”，说明角色、交接信息和决策点，支持 3。 | “用搜索和生图工具”为 2；“先核实素材、冻结文案与数值，再把非敏感摘要给生图工具”，说明选择用途及前置依赖，支持 3。 |
| 3 → 4 | 只有完整分工计划仍为 3；发现 AI 把未确认候选当结论后，用户调整交接条件并在后续执行中落实，支持 4。 | 安装了更多工具不升级；实际生图改错数值后，用户改为先用计算脚本冻结数据再交给绘图，后续按新依赖执行，支持 4。 |

### 4. 判断取舍

| 边界 | 指标 A：针对问题的具体判断标准 | 指标 B：比较利弊并说明选择 |
| --- | --- | --- |
| 2 → 3 | “按新增调用费用比较这两个方案”为 2：标准具体但缺少交付约束；“在满足离线运行和可编辑交付前提下，比较新增费用和维护步骤”，给出当前选择的约束与标准，支持 3。 | “选 SVG，因为可编辑”为 2；“PNG 分享方便，SVG 可编辑且无需生图额度，这次以 SVG 为源稿并附 PNG 预览”，比较替代方案并保留所需收益，支持 3。 |
| 3 → 4 | 只有书面标准仍为 3；实际预览暴露字体兼容问题后，用户修订比较标准并据此检查候选，支持 4。 | 仅说“我比较过”不升级；用户看到两种真实输出，指出兼容差异，据此改变/确认选择并落实对应交付，支持 4。 |

### 5. 迭代打磨

| 边界 | 指标 A：定位结果中的具体问题 | 指标 B：可执行修改并保留有效部分 |
| --- | --- | --- |
| 2 → 3 | “副标题两行的行距太小”为 2：定位了局部问题但缺少影响及验收语境；“第二行压到雷达图标签，手机预览读不清，其他区块正常”，指明位置、表现及相关条件，支持 3。 | “把字号调大”为 2；“保留称号与八维数据，将三句文案压成两句，为标签留出一行空间”，限定改动与保留项，支持 3。 |
| 3 → 4 | 只指出第一版的问题仍为 3；用户对照修订，确认遮挡已解但发现长标签换行问题，再精确定位并落实下一轮校准，支持 4。 | 单次提出完整修改仍为 3；用户根据修订效果调整间距方案，同时保留已修好的字号和数据，修订落实该反馈，支持 4。 |

### 6. 知识复用

| 边界 | 指标 A：提炼可重复使用的方法 | 指标 B：输入输出、边界与调用 |
| --- | --- | --- |
| 2 → 3 | “把这次提示词存下来再用”为 2；“将固定步骤和可变主题拆开，明确哪些材料可替换、哪些验收规则每次保留”，提炼出可复用方法，支持 3。 | “将接收选题、输出 PNG 的步骤封装为海报技能”为 2：输入输出已有但边界与调用条件未明；“接收选题和受众，输出海报，缺证显示待探索，通过技能名调用，适用于节日画像”，界定接口与范围，支持 3。 |
| 3 → 4 | 文件完整、措辞专业不自动升级；实际第二次使用暴露硬编码主题后，用户改成参数并在修订中落实，支持 4。 | 只写“支持多种输入”仍不够；调用发现缺字段时行为不清后，用户补充默认值/报错条件并在后续调用中落实，支持 4。 |

### 7. 多元表达

| 边界 | 指标 A：媒介服务内容与受众 | 指标 B：内容、结构和视觉层级配合 |
| --- | --- | --- |
| 2 → 3 | “图和文字都要”为 2；“给手机端读者用图看八维差异，短句说长处，详细依据放正文”，说明每种媒介承担的信息，支持 3。 | “标题大一点、用暖色”为 2；“称号为主标题，雷达图居中，能力短句与其对应，口号收尾”，说明层级和内容关系，支持 3。 |
| 3 → 4 | 仅要求多种文件格式不升级；用户依据手机预览发现长文抢占图表，决定把解释移到正文并在修订中落实，支持 4。 | 仅列完整层级仍为 3；看到样张中刻度像测评结论后，用户要求把趣味说明提升至图表副标题并在新稿中落实，支持 4。 |

### 8. 应变交付

| 边界 | 指标 A：具体限制及影响 | 指标 B：备用路径保留核心目标 |
| --- | --- | --- |
| 2 → 3 | “失败就换办法”为 1；“没有生图工具就用 SVG”为 2；进一步说明“无法调用位图模型，但仍需可分享且数字准确的海报”，把条件和影响连到目标，支持 3。 | “改画 SVG”为 2；“用 SVG 保留八维图、称号和口号，有渲染工具再附 PNG，缺渲染工具交付源文件”，给出可执行替代及交付边界，支持 3。 |
| 3 → 4 | 预案再完整也只支持相应的 3；实际出现模型不可用，用户依据错误/限制确认受影响部分并指导调整，后续路径落实，支持 4。 | 仅仅 Agent 自行切换不计作用户统筹；用户在实际失败后选择保留核心内容的替代方案，并在新稿中落实，支持 4。是否恢复成功另按 E 判。 |

## C、E 的单独裁决

| 分项边界 | 尚不足以升级 | 可以升级的可观察证据 |
| --- | --- | --- |
| C：2 → 3 | 只有“先做图再导出”的顺序；步骤多不等于协调多目标。 | 用户说明如何同时满足实际存在的目标/条件，例如手机可读与信息完整发生空间竞争，明确保留项、删减顺序与交付形式。 |
| C：3 → 4 | 写好了“模型不可用则 SVG”的计划，但条件没发生。 | 条件实际发生后，用户按反馈处理冲突、异常或场景变化；能指出用户作出的调整及其执行记录。无需另造复杂任务。 |
| E：1 → 2 | 只有方案、验收规则或“以后运行”的承诺。 | 有与本维相关的实际产物及有限检查/使用记录；只有输出文件存在、未见相关效果时不要推定更高等级。 |
| E：2 → 3 | 产物交付、笼统“满意”，或完成一次无前后对应关系的检查。 | 针对该维的问题，有初稿/反馈、相应修改，以及明确显示改善的使用结果或针对性复核，三者可对照。 |
| E：3 → 4 | 同一任务连续改了三轮，或说“可长期使用”。 | 方法在两个任务目标/输入条件实质不同的情境中实际使用并分别验证有效；或一次真实复杂条件交付，明确记录发生的困难、应对、保留的目标和相应检查。不同文件格式不自动算两个情境。 |

例如用户第一次指出标签遮挡，给出保留数据和字号的具体调整，随后已有修订图但只见有限检查：迭代打磨可判 `A=3,B=3,C=2,E=2 → 6.3`。不能因为评分低于预期便将“已有新图”改读为“已验证改善”；补充了什么检查，才可能改变 E。

## 如何处理评审分歧

若甲把“完整写了 SVG 兜底规则”判为应变交付 E=4，乙判为 E=1，先核对该格对应的结果证据。只有成文预案且没有发生或执行记录时，E=1；A/B 仍可能达到 3。不能取平均 E=2 或把文字完整性换成成效。

复核记录可写成：`证据 e3 是用户明确的兜底要求；A=3、B=3 的条件已满足；C=2 仅有分支安排；E=1 无实际恢复结果。若后来出现执行结果，另记新证据再复评。` 公开解释只保留非敏感摘要，不上传证据原文。默认继续突出用户已经体现的预见力和目标意识，不附带短板清单。
